# BioGT Paper Experiment Inventory

## 2026-08-01 pure BioGT joint-target rerun protocol

The runnable replacement matrix is generated by `run_paper_suite.py`. It
supersedes the historical single-target 344-task matrix for new paper results:

- every training task jointly predicts `protein,gene,rna,metabolite`;
- the model is pure BioGT (`interaction_mlp` plus BioGT Path5/RelBF), with no
  KGE, PPR, NBFNet prediction, embedding, checkpoint, or score fusion;
- frozen baselines are read from existing artifacts and are never retrained;
- GPU execution is serial (`workers=1`) and formal runs use the remote RTX5090;
- the 242 unique tasks are main (1), node-level 10-fold (10), fusion (4),
  ablation (3), direct disease-biomarker holdout (1), disease-category holdout
  (11), and frozen-manifest sensitivity (212);
- case studies are intentionally not rerun; epoch curves reuse run logs, while
  external validation and KG statistics are regenerated without model
  retraining;
- every task exports AUC-PRC, AUC-ROC, Accuracy/F1 at threshold 0.5,
  Accuracy/F1 at an F1-maximizing threshold selected only on validation, and
  exact MRR plus Hits/Recall/NDCG at K in `{1,5,10,20,50,100}`;
- node-fold and category runs train independently on their own train split.
  Loading a checkpoint trained on another split is prohibited because it can
  leak held-out edges.

The frozen strict test-once result is not rerun. New optimization, fusion,
ablation, and sensitivity comparisons use validation; predeclared node-fold,
direct-holdout, and category tasks evaluate their independent held-out split.

## Sources and scope

- Manuscript source:
  `../Nancy/PaperOfNancy/as26biogt/biogt-article.tex`
- Supplementary source:
  `../Nancy/PaperOfNancy/as26biogt/supplementary.tex`
- Model checkout:
  `.`
- Available graph data:
  `Data/merged_node.csv`, `Data/merged_edge.csv`, and `Data/marker_edge.csv`
- The manuscript calls the DNA target "DNA"; the model code calls it `gene`.
- The manuscript protocol is seed 42 unless an experiment explicitly uses
  folds. It describes a maximum of 10,000 epochs, embedding size 64, three
  HGCN layers, three Transformer layers, 16 heads, dropout 0.1, one negative
  per positive, and train/validation/test proportions of 0.8/0.1/0.1.

Action labels:

- **MUST RERUN**: new ranking metrics cannot be reconstructed from the stored
  binary metrics, or the current result depends on a model checkpoint.
- **RESUMMARIZE**: no model training is needed; existing raw outputs are enough.
- **CONDITIONAL RERUN**: existing analysis remains valid only if the final
  BioGT candidates and ranks do not change.
- **BLOCKED**: the current implementation does not faithfully implement the
  manuscript protocol and must be corrected and audited before execution.

Metric support:

- `Y-pair`: computed on held-out positives plus sampled negatives.
- `Y-full`: computed as full filtered disease-to-target ranking only when
  `--enable-full-ranking-eval --restrict-ranking-etypes-to-source-type` is used.
- `N/A`: the analysis is not a link-ranking experiment.
- Existing paper plotting/extraction scripts only understand loss, AUC-PRC,
  AUC-ROC, accuracy, and F1 unless noted otherwise.

## Command templates

These are inventory templates only. Do not execute them until the split blockers
below are resolved and a frozen run manifest has been reviewed.

### C1: single target, model, and fusion

```bash
REPO_ROOT="${REPO_ROOT:-$(pwd)}"
cd "$REPO_ROOT"

TARGET=protein
MODEL=original
FUSION=weighted
RUN_DIR="Model/experiments_paper/main/model-${MODEL}_target-${TARGET}"

python -m Model.train_test_single \
  --nodes_csv Data/merged_node.csv \
  --edges_csv Data/merged_edge.csv \
  --gpu 0 \
  --model-type "$MODEL" \
  --train_target_types "$TARGET" \
  --eval_input_type disease \
  --eval_output_types "$TARGET" \
  --split-strategy random \
  --val_split 0.1 \
  --test_split 0.1 \
  --seed 42 \
  --epochs 10000 \
  --lr 0.0001 \
  --weight_decay 0.00001 \
  --default_embed_size 64 \
  --hgcn_hidden 64 \
  --hgcn_out 64 \
  --num_gnn_layers 3 \
  --num_transformer_layers 3 \
  --transformer_heads 16 \
  --transformer_ff 512 \
  --num_latents 32 \
  --dropout 0.1 \
  --k_neg_samples 1 \
  --link-loss bce \
  --fusion-mode "$FUSION" \
  --ranking_ks 10,50,100 \
  --enable-full-ranking-eval \
  --full-ranking-source-type disease \
  --restrict-ranking-etypes-to-source-type \
  --sync-model-target-etypes \
  --skip-final-prediction \
  --metrics-output "$RUN_DIR/metrics.json" \
  --save_model_path "$RUN_DIR/model_final.pt" \
  --graph_cache_path "$RUN_DIR/cache"
```

Before use, replace the current edge-level `random` split with the audited
node-level split claimed by the manuscript. For unseen-node evaluation, do not
silently remove held-out zero-degree nodes from the message graph.

## Critical blockers and required audits

1. **Split protocol mismatch.** The manuscript claims disjoint node-level
   random splits and node-level 10-fold induced subgraphs. Current
   `RandomEdgeSplitter` and `KFoldEdgeSplitter` split edges.
2. **Disease-category ID bug.** `specific_ids` compares global node indices
   with per-type DGL IDs. It must map each original disease ID through
   `node_dglid_to_orig['disease']` or an explicit inverse map.
3. **No frozen split manifest.** Every model, fusion, and ablation comparison
   must consume identical exported train/validation/test IDs. A graph cache
   path alone is not an auditable split specification.
4. **Feature-protocol ambiguity.** Historical wrappers pass
   `--disable-sequence-features`, while the manuscript describes molecular
   sequence/structure-derived initialization. The final protocol must state
   which feature channels are active and synchronize node/type metadata.
5. **Launcher/manuscript mismatch.** The current paper-suite launcher defaults
   to 30,000 epochs and five negatives; the manuscript states 10,000 and one.
6. **Ranking support is not reporting support.** `train_test_single.py` can
   write sampled and full ranking metrics, but all manuscript plot extractors
   still parse only the legacy log line or hard-coded values. A JSON-first
   aggregator is missing.
7. **Full-ranking comparability.** Candidate IDs, test triples, query
   direction, known-positive filter graph, message graph, and tie policy must
   be identical across BioGT and every baseline. Sampled MRR/Hits values are
   not comparable with full filtered ranking.
8. **Case studies are not manifest-driven.** Exact disease IDs, checkpoint,
   candidate IDs, scores, explanation parameters, and selected paths are not
   stored together in structured output.
9. **Hyperparameter sweep is not reproducible.** The historical 212 valid
   embed=64 rows exist, but there is no portable launcher or manifest and the
   extractor contains a hard-coded macOS path.
10. **External validation is coupled to hard-coded candidates.** It is
    reproducible for the published fixed list, but must be rerun and re-curated
    if the optimized model changes E10 or E11.
